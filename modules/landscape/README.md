# Landscape — встроенный ландшафт (модуль `landscape`)

Встроенная в движок система ландшафта в духе Landscape из UE4/UE5:
GPU Quadtree + Screen-Space Error + indirect draw, микродетализация,
до 16 слоёв материалов, кисти скульптинга и покраски, размеры до 16 × 16 км.

## Классы

| Класс | Назначение |
|---|---|
| `Landscape3D` (Node3D) | Узел ландшафта: рендер, LOD, коллизия, запросы высоты/нормали, raycast. |
| `LandscapeData` (Resource) | Высоты (float32, метры), веса слоёв (4 × RGBA8 = 16 слоёв), дыры. Тайловое хранилище, файл `.lsdata` со стримингом. Импорт/экспорт карт высот. |
| `LandscapeLayer` (Resource) | Слой материала: albedo, normal, roughness, AO, height, тайлинг, height blend, трипланар, смещение. |
| `LandscapeBrush` (RefCounted) | Инструменты кистей, работают и в редакторе, и в рантайме. |
| `WorldStreaming` (синглтон, модуль `streaming`) | Общее ядро стриминга: очередь задач с приоритетами на фоновых потоках, источники стриминга, бюджеты памяти (мониторы Streaming/* в отладчике). |
| `StreamingSource3D` (Node3D, модуль `streaming`) | Источник стриминга (например, игрок): вокруг него строится коллизия и подгружаются данные. |

Разрешение данных — до 16384 сэмплов на сторону; мировой размер
`(size - 1) * vertex_spacing` (например, 16384 × 1 м ≈ 16 км, 8193 × 2 м ≈ 16 км).

## Как работает рендер

1. **CPU-дерево границ** (`LandscapeLodTree`): для каждого узла квадродерева хранится
   min/max высоты и геометрическая ошибка (макс. отклонение сетки узла от более
   детальной сетки; монотонна по дереву). Обновляется только для изменённых областей.
2. **GPU-обход** (`shaders/landscape_lod.glsl`, режим `MODE_TRAVERSE`): по одному
   indirect-диспатчу на уровень. Каждый узел проходит frustum culling, затем его
   ошибка проецируется на экран (`error * K / distance`). Если она больше
   `lod_pixel_error` — узел делится (дети дописываются в список следующего уровня,
   аргументы следующего диспатча считаются атомарно на GPU), иначе патч пишется
   **прямо в буфер инстансов indirect MultiMesh**.
3. **Сшивка** (`MODE_STITCH`): по битам разбиения ищется уровень соседей каждого
   патча; вершинный шейдер схлопывает рёбра на сетку более грубого соседа
   (или интерполирует вдоль ребра при очень большой разнице уровней) — без трещин.
   Все позиции вычисляются в целочисленной сетке, поэтому общие вершины бит-в-бит совпадают.
4. **Отрисовка**: стандартный Forward+/Mobile рендерер рисует MultiMesh через
   `draw_list_draw_indirect` — число инстансов пишет GPU, CPU ничего не читает обратно.
5. **Тени**: отдельный список патчей без frustum culling (`shadow_lod_bias`,
   `shadow_distance`), чтобы горы вне кадра отбрасывали тени.
6. **Микродетализация**: ниже разрешения карты высот квадродерево может делиться ещё
   на `micro_detail_levels` уровней; ошибка микро-уровня = амплитуда смещения слоёв.
   Поверхность смещается по нормали картами высот слоёв (`LandscapeLayer.displacement`),
   смещение плавно гаснет с расстоянием (функция только от позиции — трещин нет),
   мип-уровень карты высот подбирается под плотность вершин.


Дыры (инструмент Visibility) хранятся отдельной маской, которая выделяется только
при первом использовании; шейдер с `discard` подключается только для ландшафтов с дырами
(чтобы не терять early-Z), в коллизии дыры передаются как NaN-сэмплы HeightMapShape3D.

## Стриминг

Данные хранятся тайлами по 128 × 128 текселей для каждого мип-уровня (пирамида до 8 текселей):
высоты — точной подвыборкой (мип m содержит точные высоты вершин на этом разрешении),
веса и дыры — фильтром [1 2 1]. Мип 0 — редактируемый источник, остальные пересчитываются
только в изменённых областях.

**Файл `.lsdata`** (создаётся кнопкой в доке или `ResourceSaver.save(data, "…/x.lsdata")`):
заголовок, индекс тайлов, дерево LOD и сжатые zstd тайлы. При загрузке читается только заголовок
(16k × 16k с 16 слоями открывается за ~20 мс), тайлы подгружаются по требованию фоновыми потоками
`WorldStreaming`. Никогда не изменявшиеся тайлы не занимают ни памяти, ни места на диске.

**CPU**: кэш тайлов с LRU и бюджетом `rendering/landscape/streaming/cpu_cache_size_mb` (512 МБ).
Изменённые тайлы при вытеснении сбрасываются во временный overlay-файл до сохранения —
поэтому импорт, заливка слоёв и правки работают с ограниченной памятью даже на 16 км.

**GPU**: пул страниц (`streaming_pool_size`, по умолчанию 256 МБ) — слоты текстурных массивов
129 × 129 (тайл + рамка в 1 тексель) с высотами, нормалями, весами и дырами, плюс таблица страниц.
Каждый кадр CPU выбирает нужные страницы: узлы квадродерева, до которых может дойти GPU-обход
(тот же критерий SSE, без отсечения по пирамиде видимости — поворот камеры не требует подгрузки),
и страницы, чьё разрешение соответствует размеру текселя на экране (виртуальное текстурирование,
`texture_lod_bias`). Страницы сортируются по расстоянию относительно размера, лишние не помещаются
в пул, наименее нужные вытесняются. Сборка страниц (включая нормали) идёт на фоновых потоках.
- GPU-обход делит узел, только если страницы его детей загружены, иначе рисует его грубее.
- Вершины читают точные высоты из любого загруженного мипа, где вершина лежит на сетке, —
  общие вершины соседних патчей совпадают бит-в-бит, трещин нет при любом наборе страниц.
- Фрагментный шейдер берёт самую детальную загруженную страницу (fallback на грубые мипы).
- При редактировании затронутые страницы пересобираются сразу (сначала грубые), остальные
  вытесняются и подгружаются заново — загруженные данные всегда актуальны.

**Коллизия** строится тайлами вокруг `StreamingSource3D` (или камеры) в радиусе `collision_radius`,
тайлы данных для неё подгружаются асинхронно.

Статистика: `Landscape3D.get_statistics()` (страницы, пул, кэш CPU), док редактора,
мониторы `Streaming/Landscape CPU`, `Streaming/Landscape GPU`, `Streaming/Queued Jobs`.

## Материал

Встроенный шейдер (`Landscape3D.get_builtin_shader_code()`): на пиксель выбираются
4 слоя с наибольшим весом, смешивание по весам или по высоте (как `LB_HeightBlend`),
трипланар для скал, отладочные режимы (`debug_view`: уровни LOD, патчи, нормали,
доминирующий слой, мип-уровни страниц стриминга). Можно подменить своим шейдером через `shader_override`.

## Редактор

При выделении `Landscape3D` появляется док **Landscape**:

- **Manage** — создание данных (разрешение, шаг вершин, пресеты до 16384; сохраняются в `.lsdata`),
  импорт/экспорт карт высот (16-bit PNG, R16/RAW, EXR), ресемплинг,
  отладочный режим отображения (LOD, патчи, нормали, слои, стриминг) и Freeze LOD.
- **Sculpt** — Sculpt, Smooth, Flatten, Ramp, Noise, Erosion, Terrace, Visibility (дыры).
- **Paint** — список слоёв (добавить/удалить/залить, импорт весовой карты слоя),
  Paint, Smooth, Flatten, Noise.
- **Brush Settings** — размер, falloff, сила, тип falloff (Smooth/Linear/Spherical/Tip),
  alpha-кисть с поворотом, настройки инструмента.

Управление: ЛКМ — применить, Shift+ЛКМ — инвертировать (опустить/стереть),
Ctrl+ЛКМ — пипетка (высота для Flatten, слой/вес для Paint), `[` / `]` — размер кисти.
Все операции поддерживают Undo/Redo. В доке выводится статистика GPU LOD
(патчи, треугольники, переполнение бюджета `max_patches`) и стриминга (страницы, пул GPU, кэш CPU).

Данные сохраняйте в `.lsdata` (кнопка создания делает это сама) — только так они стримятся;
`.res`/`.tres` загружаются целиком.

## Рантайм API (пример)

```gdscript
var brush := LandscapeBrush.new()
brush.tool = LandscapeBrush.TOOL_SCULPT
brush.size = 6.0
brush.strength = 1.0
brush.invert = true # воронка от взрыва
brush.apply($Landscape3D.data, $Landscape3D.global_to_local(hit_position))

var h := $Landscape3D.get_height_at(player.global_position)
var hit := $Landscape3D.raycast(from, direction)
```

## Ограничения текущей версии / следующие шаги

- Стриминг сцены по ячейкам (аналог World Partition) для остальных узлов — следующий этап,
  ядро (`WorldStreaming`) уже есть.
- Нет edit layers (неразрушающих слоёв редактирования), копирования регионов, травы.
- Высоты хранятся в float32 (сжатие zstd по байтовым плоскостям), без квантования в 16 бит.
- Дыры отсекаются по пикселям и вырезаются из коллизии (только Jolt), квадродерево их не учитывает.
- LOD и выбор страниц считаются для одной камеры (`lod_camera_path` или текущая камера вьюпорта).
- Compatibility (OpenGL) рендерер не рисует ландшафт (нужны compute-шейдеры);
  коллизия и запросы работают.
