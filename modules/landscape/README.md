# Landscape — встроенный ландшафт (модуль `landscape`)

Встроенная в движок система ландшафта в духе Landscape из UE4/UE5:
GPU Quadtree + Screen-Space Error + indirect draw, микродетализация,
до 16 слоёв материалов, кисти скульптинга и покраски, размеры до 16 × 16 км.

## Классы

| Класс | Назначение |
|---|---|
| `Landscape3D` (Node3D) | Узел ландшафта: рендер, LOD, коллизия, запросы высоты/нормали, raycast. |
| `LandscapeData` (Resource) | Высоты (float32, метры), веса слоёв (4 × RGBA8 = 16 слоёв), дыры. Тайловое хранилище, файл `.lsdata` со стримингом. Импорт/экспорт карт высот. |
| `LandscapeLayer` (Resource) | Слой материала: albedo, normal, roughness, AO, height, тайлинг, height blend, трипланар, смещение. |
| `LandscapeBrush` (RefCounted) | Инструменты кистей, работают и в редакторе, и в рантайме. |
| `LandscapeSpline3D` (Node3D) | Сплайн дороги, реки, ручья или озера: вытягивает сетку вдоль кривой и деформирует/красит ландшафт под ней (аналог Landscape Splines / Water в UE5). |
| `LandscapeWaterMaterial` (Material) | Встроенный шейдер воды: течение по сплайну, глубина, преломление, пена у берегов и на перекатах. |
| `LandscapeRoadMaterial` (Material) | Встроенный шейдер дороги: асфальт/грунт/гравий, разметка, неровные края, мокрый асфальт и лужи. |
| `LandscapeFoliage3D` (Node3D) | Растительность, нарисованная на ландшафте (аналог Foliage в UE4): инстансы по типам, разбитые на чанки, LOD на уровне инстансов, следование за рельефом. |
| `LandscapeFoliageType` (Resource) | Тип растительности (аналог Foliage Type): меши уровней детализации, дальность отсечения, плотность, масштаб, поворот, выравнивание, фильтры по уклону, высоте и слоям. |
| `WorldStreaming` (синглтон, модуль `streaming`) | Общее ядро стриминга: очередь задач с приоритетами на фоновых потоках, источники стриминга, бюджеты памяти (мониторы Streaming/* в отладчике). |
| `StreamingSource3D` (Node3D, модуль `streaming`) | Источник стриминга (например, игрок): вокруг него строится коллизия и подгружаются данные. |

Разрешение данных — до 16384 сэмплов на сторону; мировой размер
`(size - 1) * vertex_spacing` (например, 16384 × 1 м ≈ 16 км, 8193 × 2 м ≈ 16 км).

## Как работает рендер

1. **CPU-дерево границ** (`LandscapeLodTree`): для каждого узла квадродерева хранится
   min/max высоты и геометрическая ошибка (макс. отклонение сетки узла от более
   детальной сетки; монотонна по дереву). Обновляется только для изменённых областей.
2. **GPU-обход** (`shaders/landscape_lod.glsl`, режим `MODE_TRAVERSE`): по одному
   indirect-диспатчу на уровень. Каждый узел проходит frustum culling, затем его
   ошибка проецируется на экран (`error * K / distance`). Если она больше
   `lod_pixel_error` — узел делится (дети дописываются в список следующего уровня,
   аргументы следующего диспатча считаются атомарно на GPU), иначе патч пишется
   **прямо в буфер инстансов indirect MultiMesh**.
3. **Сшивка** (`MODE_STITCH`): по битам разбиения ищется уровень соседей каждого
   патча; вершинный шейдер схлопывает рёбра на сетку более грубого соседа
   (или интерполирует вдоль ребра при очень большой разнице уровней) — без трещин.
   Все позиции вычисляются в целочисленной сетке, поэтому общие вершины бит-в-бит совпадают.
4. **Отрисовка**: стандартный Forward+/Mobile рендерер рисует MultiMesh через
   `draw_list_draw_indirect` — число инстансов пишет GPU, CPU ничего не читает обратно.
5. **Тени**: отдельный список патчей без frustum culling (`shadow_lod_bias`,
   `shadow_distance`), чтобы горы вне кадра отбрасывали тени.
6. **Микродетализация**: ниже разрешения карты высот квадродерево может делиться ещё
   на `micro_detail_levels` уровней; ошибка микро-уровня = амплитуда смещения слоёв.
   Поверхность смещается по нормали картами высот слоёв (`LandscapeLayer.displacement`),
   смещение плавно гаснет с расстоянием (функция только от позиции — трещин нет),
   мип-уровень карты высот подбирается под плотность вершин.


Дыры (инструмент Visibility) хранятся отдельной маской, которая выделяется только
при первом использовании; шейдер с `discard` подключается только для ландшафтов с дырами
(чтобы не терять early-Z), в коллизии дыры передаются как NaN-сэмплы HeightMapShape3D.

## Стриминг

Данные хранятся тайлами по 128 × 128 текселей для каждого мип-уровня (пирамида до 8 текселей):
высоты — точной подвыборкой (мип m содержит точные высоты вершин на этом разрешении),
веса и дыры — фильтром [1 2 1]. Мип 0 — редактируемый источник, остальные пересчитываются
только в изменённых областях.

**Файл `.lsdata`** (создаётся кнопкой в доке или `ResourceSaver.save(data, "…/x.lsdata")`):
заголовок, индекс тайлов, дерево LOD и сжатые zstd тайлы. При загрузке читается только заголовок
(16k × 16k с 16 слоями открывается за ~20 мс), тайлы подгружаются по требованию фоновыми потоками
`WorldStreaming`. Никогда не изменявшиеся тайлы не занимают ни памяти, ни места на диске.

**CPU**: кэш тайлов с LRU и бюджетом `rendering/landscape/streaming/cpu_cache_size_mb` (512 МБ).
Изменённые тайлы при вытеснении сбрасываются во временный overlay-файл до сохранения —
поэтому импорт, заливка слоёв и правки работают с ограниченной памятью даже на 16 км.

**GPU**: пул страниц (`streaming_pool_size`, по умолчанию 256 МБ) — слоты текстурных массивов
129 × 129 (тайл + рамка в 1 тексель) с высотами, нормалями, весами и дырами, плюс таблица страниц.
Каждый кадр CPU выбирает нужные страницы: узлы квадродерева, до которых может дойти GPU-обход
(тот же критерий SSE, без отсечения по пирамиде видимости — поворот камеры не требует подгрузки),
и страницы, чьё разрешение соответствует размеру текселя на экране (виртуальное текстурирование,
`texture_lod_bias`). Страницы сортируются по расстоянию относительно размера, лишние не помещаются
в пул, наименее нужные вытесняются. Сборка страниц (включая нормали) идёт на фоновых потоках.
- GPU-обход делит узел, только если страницы его детей загружены, иначе рисует его грубее.
- Вершины читают точные высоты из любого загруженного мипа, где вершина лежит на сетке, —
  общие вершины соседних патчей совпадают бит-в-бит, трещин нет при любом наборе страниц.
- Фрагментный шейдер берёт самую детальную загруженную страницу (fallback на грубые мипы).
- При редактировании затронутые страницы пересобираются сразу (сначала грубые), остальные
  вытесняются и подгружаются заново — загруженные данные всегда актуальны.

**Коллизия** строится тайлами вокруг `StreamingSource3D` (или камеры) в радиусе `collision_radius`,
тайлы данных для неё подгружаются асинхронно.

Статистика: `Landscape3D.get_statistics()` (страницы, пул, кэш CPU), док редактора,
мониторы `Streaming/Landscape CPU`, `Streaming/Landscape GPU`, `Streaming/Queued Jobs`.

## Материал

Встроенный шейдер (`Landscape3D.get_builtin_shader_code()`): на пиксель выбираются
4 слоя с наибольшим весом, смешивание по весам или по высоте (как `LB_HeightBlend`),
трипланар для скал, отладочные режимы (`debug_view`: уровни LOD, патчи, нормали,
доминирующий слой, мип-уровни страниц стриминга). Можно подменить своим шейдером через `shader_override`.

## Редактор

При выделении `Landscape3D` появляется док **Landscape**:

- **Manage** — создание данных (разрешение, шаг вершин, пресеты до 16384; сохраняются в `.lsdata`),
  импорт/экспорт карт высот (16-bit PNG, R16/RAW, EXR), ресемплинг,
  отладочный режим отображения (LOD, патчи, нормали, слои, стриминг) и Freeze LOD.
- **Sculpt** — Sculpt, Smooth, Flatten, Ramp, Noise, Erosion, Terrace, Visibility (дыры).
- **Paint** — список слоёв (добавить/удалить/залить, импорт весовой карты слоя),
  Paint, Smooth, Flatten, Noise.
- **Brush Settings** — размер, falloff, сила, тип falloff (Smooth/Linear/Spherical/Tip),
  alpha-кисть с поворотом, настройки инструмента.
- **Splines** и **Foliage** — дороги и водоёмы, растительность (см. разделы ниже).

Управление: ЛКМ — применить, Shift+ЛКМ — инвертировать (опустить/стереть),
Ctrl+ЛКМ — пипетка (высота для Flatten, слой/вес для Paint), `[` / `]` — размер кисти.
Все операции поддерживают Undo/Redo. В доке выводится статистика GPU LOD
(патчи, треугольники, переполнение бюджета `max_patches`) и стриминга (страницы, пул GPU, кэш CPU).

Данные сохраняйте в `.lsdata` (кнопка создания делает это сама) — только так они стримятся;
`.res`/`.tres` загружаются целиком.

## Сплайны: дороги, реки, ручьи, озёра

`LandscapeSpline3D` — дочерний узел (на любой глубине) `Landscape3D`. Тип (`type`) задаёт
профиль деформации, сетку и материал по умолчанию:

| Тип | Сетка | Ландшафт |
|---|---|---|
| `TYPE_ROAD` | лента по ширине дороги + юбка вниз по краям | выравнивается под полотно (с наклоном `tilt`), плавный спад `terrain_falloff` по бокам и `terrain_end_falloff` на концах |
| `TYPE_RIVER`, `TYPE_STREAM` | лента поверхности воды (чуть шире русла, `water_overlap`) | русло глубиной `depth`, форма дна `channel_shape`, берега поднимаются до `bank_height` над водой |
| `TYPE_LAKE` | плоская сетка внутри замкнутого контура на высоте узла | котловина глубиной `depth` с береговой зоной `shore_width` |

Кривая — центростремительный Catmull-Rom через точки (без петель и выбросов), у каждой точки
свои ширина, глубина, наклон и скорость течения (плавная интерполяция между точками).
Кривая разбивается по длине дуги (`sample_spacing`) и дополнительно по кривизне.

### Неразрушающая деформация (как в UE5)

Сплайны не «запекают» изменения в ландшафт навсегда. В хранилище есть разреженный
**базовый слой** (высоты и веса) — только для тайлов 128 × 128 под сплайнами:

- финальные данные тайла = базовый слой + все сплайны, наложенные по `terrain_priority`;
- кисти (скульпт/покраска) в редакторе пишут в базовый слой, после чего сплайны накладываются
  снова — можно поднять гору под дорогой, и дорога останется ровной;
- сдвинули или удалили сплайн — затронутые тайлы пересобираются из базового слоя;
  тайл, под которым не осталось сплайнов, возвращается к базовому слою и освобождает его;
- для каждого сплайна в `LandscapeData.spline_records` хранятся хеши его блоков
  (по одному на сегмент между точками): после перезагрузки сцены или правки одной точки
  пересчитываются только блоки, которые реально изменились; сплайны, удалённые из сцены
  при закрытом редакторе, обнаруживаются и их след убирается;
- базовый слой сохраняется в `.lsdata` (формат версии 2, файлы без сплайнов пишутся как раньше)
  и во встроенных данных (свойство `base_tiles`).

В рантайме компоновщик не регистрируется: кисти пишут прямо в финальные данные
(воронка от взрыва на дороге остаётся), сплайны не пересчитываются, пока их не двигают.

### Оптимизация

- **Чанки**: сетка режется на куски длиной `chunk_length` (у озера — блоки 32 × 32 ячейки),
  каждый — отдельный экземпляр с собственным AABB, поэтому отсекаются по пирамиде
  видимости и окклюзии независимо.
- **LOD**: у каждого чанка индексные LOD (прореживание рядов вдоль сплайна в 2/4/8 раз, ошибка
  = максимальное отклонение сетки), `lod_bias` управляет переключением.
- **Дальность видимости**: `visibility_range` с плавным исчезновением (`FADE_SELF`);
  `0` — видно всегда.
- **Ленивая сборка**: чанки строятся только вблизи камеры (в пределах дальности видимости),
  не более 16 чанков и 3 мс за кадр; дальние чанки не занимают памяти.
- Вода и дороги не отбрасывают тени по умолчанию (`cast_shadows`).
- Деформация ландшафта пересчитывается только в изменённых тайлах, в редакторе —
  с задержкой ~80 мс после последней правки (но не реже чем раз в 250 мс), чтобы перетаскивание
  точек оставалось плавным; затронутые страницы стриминга и коллизия обновляются точечно.

### Встроенные шейдеры

`LandscapeWaterMaterial` (реки, ручьи, озёра):

- течение по направлению сплайна (flow mapping в две фазы без рывков), скорость — из точек
  сплайна (`flow_speed`), у берегов замедляется (`bank_slowdown`); у озёр — ветер (`wind_velocity`);
- цвет по глубине (поглощение `clarity` между `shallow_color` и `deep_color`), преломление дна,
  френель, отражения;
- пена у берегов (по разнице глубины), на быстрых участках (`flow_foam`), плавное
  исчезновение у краёв сетки (`edge_fade`), лёгкая волна вершин (`wave_height`);
- встроенные бесшовные текстуры ряби (normal) и пены генерируются процедурно.

`LandscapeRoadMaterial`: пресеты асфальт/грунт/гравий (`apply_preset`), процедурная текстура
с зерном и износом (или свои `albedo_texture`/`normal_texture`), разметка (полосы, сплошная/пунктир,
осевая, краевые линии), грязные неровные края с alpha scissor, мокрый асфальт и лужи.

Оба материала можно преобразовать в `ShaderMaterial` (контекстное меню ресурса
**Convert to ShaderMaterial**) и доработать шейдер вручную. Атрибуты вершин:

- дорога: `UV` = (поперёк 0..1, метры вдоль), `UV2` = (смещение от центра, полуширина);
- река/ручей: `UV` = (метры вдоль, смещение от центра), `UV2.x` = скорость течения,
  `COLOR` = (турбулентность по уклону, |смещение| / полуширина, 0, затухание на концах);
- озеро: `UV` = мировые XZ узла.

### Редактор

Вкладка **Splines** в доке Landscape:

- кнопки **Road / River / Stream / Lake** создают сплайн и включают режим рисования
  (ЛКМ — добавить точку на ландшафт или вставить между существующими, Enter/Esc/ПКМ — завершить);
- список сплайнов ландшафта; точки выделяются и двигаются стандартным гизмо трансформации
  (есть рамочное выделение), ширина — ручками по бокам точки;
- ширина, глубина, наклон и скорость течения выделенных точек, **Snap Points to Terrain**
  (привязка к ландшафту без учёта сплайнов, у озера — уровень по берегу), **Make Downhill**
  (река всегда течёт вниз), **Reverse**, **Rebuild All**, Delete — удалить точки.

Все операции поддерживают Undo/Redo.

## Растительность (Foliage)

`LandscapeFoliage3D` — дочерний узел (на любой глубине) `Landscape3D`, на который кистью наносятся
деревья, кусты, трава, камни (как Foliage Mode в UE4). Узел хранит инстансы нескольких типов
`LandscapeFoliageType`; тип — отдельный ресурс, его можно сохранить в `.tres` и использовать
в нескольких сценах.

### Тип растительности

| Группа | Настройки |
|---|---|
| Меш | `mesh` (LOD 0), `material_override`, строка **LODs** с кнопкой **Edit LODs...** |
| Painting | `density` — инстансов на 100 м² (10 × 10 м, как «на 1000 uu²» в UE), `radius` — минимальное расстояние между инстансами типа |
| Scale | `scaling` (Uniform / Free / Lock Horizontal), `scale_min/max`, `vertical_scale_min/max` |
| Placement | `offset_min/max` (по вертикали от земли), `align_to_normal` + `align_max_angle`, `random_yaw`, `random_pitch` |
| Filters | `slope_min/max`, `height_min/max` (глобальная высота), `layers` / `exclude_layers` (слои ландшафта, компактная сетка 16 кнопок) и `layer_min_weight` |

**Уровни детализации** не вложены в инспектор: строка **LODs** показывает сводку
(«3 levels · culled at 300 m»), а кнопка открывает **отдельное окно LOD**:

- линейка расстояний с цветными полосами уровней, границы (начала LOD и дальность отсечения)
  перетаскиваются мышью; более тёмные полосы — уровни без теней, серая — отсечено;
- таблица уровней: меш (пустой — меш предыдущего уровня, например уровень, который только
  отключает тени), с какого расстояния, до какого, тени, число треугольников, удаление;
- **Cull Distance** (0 — не отсекается), **Cull Random** (инстансы исчезают постепенно на этой доле
  дальности, каждый на своём расстоянии, — прореживание вместо резкой границы),
  **LOD Transition** (гистерезис смены уровня, чтобы не было мерцания на границе);
- все изменения видны сразу во вьюпорте и поддерживают Undo/Redo.

В файле ресурса уровни хранятся как `lod_count` и `lod_<n>/mesh`, `lod_<n>/start_distance`,
`lod_<n>/cast_shadows`; из скриптов — `add_lod()`, `set_lod_*()`, `remove_lod()`.
Окно открывается и из вкладки Foliage (кнопка **LODs...**).

### Рендер: чанки

Инстансы хранятся в пространстве ландшафта и раскладываются по квадратным ячейкам
(`chunk_size`, 32 м по умолчанию), отдельно для каждого типа:

1. Каждая ячейка рисуется своими MultiMesh — по одному на уровень детализации — с общими границами
   ячейки, поэтому ячейки независимо отсекаются по пирамиде видимости и окклюзии (HZB).
2. Уровень выбирается на CPU по расстоянию от камеры (та же камера, что у LOD ландшафта):
   - ячейка целиком внутри одной полосы LOD (с учётом гистерезиса) рисуется этим уровнем целиком
     и не обновляется, пока не выйдет из полосы;
   - ячейка за дальностью отсечения не имеет ресурсов рендера вовсе;
   - ячейка, которую пересекает граница LOD или отсечения, сортируется по инстансам
     (с гистерезисом `lod_transition`); пересортировка — только когда камера сдвинулась,
     а буферы перезагружаются только для уровней, в которых инстансы действительно поменялись.
3. Обновления идут от ближних ячеек к дальним, с бюджетом ~3 мс за кадр.
4. `INSTANCE_CUSTOM.x` — случайное число инстанса (как PerInstanceRandom в UE) для вариаций в шейдере.
5. `lod_distance_scale` узла умножает все дальности (настройка качества).

Статистика (`get_statistics()`, вкладка Foliage): ячейки, отрисованные ячейки, ячейки с сортировкой
по инстансам, батчи, отрисованные инстансы, время обновления.

**Следующий шаг — GPU Indirect** (по результатам тестирования чанков): те же данные ячеек загружаются
на GPU один раз, compute-шейдер (как обход квадродерева ландшафта) отсекает инстансы по пирамиде
и HZB, выбирает LOD и пишет их прямо в буферы indirect MultiMesh (`multimesh_allocate_data(..., use_indirect)`),
без участия CPU. Сигнал к переходу — большое число ячеек с сортировкой по инстансам и время
обновления в статистике на плотной траве.

### Следование за рельефом

Каждый инстанс помнит смещение от земли и нормаль, по которой выровнен. Когда высоты ландшафта
меняются (кисти, импорт, сплайны, изменения в рантайме), инстансы в изменённой области ставятся
на новый рельеф и доворачиваются на изменение нормали (`follow_terrain`). `snap_to_terrain()` —
вручную.

### Редактор

Вкладка **Foliage** в доке Landscape (появляется и при выделении `LandscapeFoliage3D`):

- узел растительности ландшафта (кнопка **New** создаёт его);
- палитра типов с миниатюрами мешей и числом инстансов: галочка — тип участвует в рисовании;
  меши и типы можно перетащить на палитру из FileSystem, меню **Add** — новый тип или из файлов,
  двойной щелчок / **Edit** — тип в инспекторе (док не закрывается), **LODs...** — окно LOD;
- инструменты: **Paint** (добивает плотность типа в кисти, Shift — стирание), **Erase** (оставляет
  `Erase Density`), **Single** (один инстанс под курсором), **Reapply** (применить текущие настройки
  размещения и фильтры типа к инстансам в кисти);
- **Fill Landscape...** — заполнить весь ландшафт отмеченными типами по их плотности и фильтрам
  (с оценкой числа инстансов), **Clear** — удалить инстансы отмеченных типов;
- размер кисти (`[` / `]`), Paint Density, Erase Density.

Все операции поддерживают Undo/Redo (снимки затронутых ячеек).

Рисование, добивающее плотность: в круге кисти берутся случайные точки, доля прошедших фильтры
оценивает, какая часть кисти подходит типу, и добавляется ровно столько, сколько не хватает
до плотности, — повторные мазки по одному месту не переполняют его.

### Хранение

Типы — свойство `foliage_types`, инстансы — `instance_data` (по массиву байт на тип: 16 float на
инстанс, байтовые плоскости, zstd). В `.tscn` массивы байт пишутся в base64, так что сцены остаются
компактными.

```gdscript
var foliage: LandscapeFoliage3D = $Landscape3D/Foliage
var trees := foliage.add_foliage_type(preload("res://foliage/pine.tres"))
foliage.paint(trees, hit_position, 15.0)          # кисть: до плотности типа
foliage.fill(trees, Rect2(0, 0, 512, 512))        # область в пространстве ландшафта
foliage.remove_instances_in_radius(trees, player.global_position, 2.0) # срубили дерево
for xform in foliage.get_instances_in_radius(trees, player.global_position, 30.0):
    print(xform.origin)
```

## Ограничения текущей версии / следующие шаги

- Стриминг сцены по ячейкам (аналог World Partition) для остальных узлов — следующий этап,
  ядро (`WorldStreaming`) уже есть.
- Из неразрушающих слоёв редактирования есть только базовый слой под сплайнами
  (произвольных edit layers и копирования регионов нет).
- Растительность: пока без коллизии инстансов, инструмента выделения/перемещения отдельных
  инстансов и процедурной травы (Landscape Grass Type); кисть рисует только по ландшафту;
  выбор LOD — на CPU по чанкам (следующий шаг — GPU Indirect, см. выше).
- Сплайны не пересекаются друг с другом «умно»: перекрёстки дорог и мосты собираются
  из нескольких сплайнов с разным `terrain_priority`.
- Высоты хранятся в float32 (сжатие zstd по байтовым плоскостям), без квантования в 16 бит.
- Дыры отсекаются по пикселям и вырезаются из коллизии (только Jolt), квадродерево их не учитывает.
- LOD и выбор страниц считаются для одной камеры (`lod_camera_path` или текущая камера вьюпорта).
- Compatibility (OpenGL) рендерер не рисует ландшафт (нужны compute-шейдеры);
  коллизия и запросы работают.
